GROUND-TRUTH ACQUISITION · IIT GUWAHATI SUMMER PROJECT

Interactive Video Curation & Ground-Truth Acquisition Dashboard for Broadcast Media

An internal tool that ingests YouTube news broadcasts, plays them in a custom browser player, and lets a reviewer draw bounding boxes on paused frames — text blocks, objects, keyframes — with every annotation saved immediately to a relational database, and OCR pre-filling extracted text automatically.

▶ Watch the walkthrough GitHub repository
01

What this project does

Broadcast newsrooms accumulate huge volumes of raw footage that need to be turned into structured, labeled data before any downstream analysis or model training can happen. This dashboard is that labeling step: a reviewer pastes a YouTube URL, the backend downloads and serves the video locally, and the reviewer marks up regions of interest directly on the video frame. Every box — its coordinates, its label, its timestamp, and any text inside it — is written straight to a database, so nothing lives only in the browser tab.

  • Ingest — paste a YouTube URL (or batch-paste 30+), the backend downloads it with yt-dlp in the background.
  • Annotate — pause the video, draw a box, pick a label (text_block / object / keyframe).
  • Auto-fill — Tesseract OCR reads the text inside each box the moment it's drawn.
  • Persist — every save is an immediate write to SQLite; restarting the server loses nothing.

03

Architecture

The system is split into two decoupled halves that only ever talk over HTTP: a FastAPI backend that owns the video files and the database, and a React frontend that owns the drawing interaction.

INPUTYouTube URL
↓
yt-dlp downloads the video once, served locally as static files
BACKENDFastAPI + SQLAlchemy
↓
served over HTTP — no embedded YouTube player, so canvas pixel access isn't cross-origin-blocked
FRONTEND<video> + <canvas> overlay
↓
on box release: crop the frame → run OCR → POST the annotation
STORAGESQLite — videos + annotations tables

Database schema (see backend/app/models.py):

  • videos — id, youtube_url, title, duration_sec, local_path, status, processed_at
  • annotations — id, video_id, timestamp_sec, bbox_x/y/w/h (normalized 0–1), label, extracted_text, thumbnail_path

Bounding box coordinates are stored normalized between 0 and 1 rather than in pixels, so a box drawn at any window size or video resolution is reconstructed correctly regardless of how large the player is rendered later.

04

Extension: long-form video & template-change detection

For multi-hour broadcast recordings, manually scrubbing through every minute isn't practical. A companion script extends the pipeline with automatic template-change detection: it samples the video at a fixed interval, fingerprints each sampled frame, and only surfaces a frame when it differs sharply from the previous one — i.e. exactly when the on-screen graphics layout changes. A standalone, server-free HTML annotator then lets a reviewer draw boxes on just those candidate frames and export the whole labeled set as CSV/JSON.

Why this matters
A 12-hour broadcast recording produces a few hundred meaningful template transitions rather than tens of thousands of near-duplicate frames — turning an unreviewable dataset into one a single person can annotate in an afternoon.
